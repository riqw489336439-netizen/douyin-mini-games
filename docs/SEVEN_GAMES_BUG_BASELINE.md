# 七款抖音小游戏统一 Bug 基线与验收门禁

适用范围：弹跳球、影子小猫、合成宠物、极速跑酷、重力企鹅、镜像机器人、时间小偷。

> 本文把此前 Cocos Creator / 抖音开发者工具 / 审核过程中实际遇到的问题固化为七款共同回归基线。任何“通过”必须区分源码静态检查、Cocos 编辑器运行、抖音开发者工具、真机四个层级；未实际执行不得标记通过。

## P0：阻断上架或核心游玩的缺陷

### 1. Cocos 工程与首场景
- 导入目录必须直接包含 `assets` 与 `package.json`，避免选错外层目录导致项目无法识别。
- 必须存在可启动首场景，Bootstrap/入口组件必须真实挂载；禁止只存在脚本但没有场景入口。
- Canvas + Camera + UI_2D 必须匹配，Camera visibility 覆盖 UI_2D，避免灰屏/空白。
- 首屏必须在冷启动、重新进入、切后台恢复后均可见。
- 运行 10 分钟不得出现黑屏、白屏、崩溃、核心素材消失。

### 2. 输入与按钮
- 所有视觉按钮必须有真实响应，触摸区域覆盖视觉区域。
- 禁止按钮重叠、穿透点击、一次触摸重复触发。
- 首页、关卡页、教程、暂停、结算必须都有确定的返回链路。
- 暂停/切后台后不得继续计时、移动、发奖或重复结算。
- 最终机关/目标完成与出口条件同一次交互满足时，应直接完成，不要求多点一次。

### 3. 存档与状态
- 存档 JSON 损坏、字段缺失、旧版本字段必须安全回退。
- 解锁关卡必须限制在合法范围；星级/金币/道具不得出现 NaN、负数或越界。
- 结算、复活、广告奖励必须幂等，防止重复回调造成重复发奖。
- 重开、下一关、返回首页后必须清理上一局运行态引用。

### 4. 激励广告
- UI 写“看广告获得/复活/护盾/道具”时，功能必须真实接通；未接通不得保留伪按钮。
- 仅由用户明确点击触发，不自动弹出。
- 标准链路：load -> show -> close/error -> 恢复可操作状态。
- 完整观看才发奖；中途关闭不发奖；一次观看只发一次。
- load/show/error/timeout 后必须释放 pending 状态，允许玩家继续或重试。
- 广告不可作为正常通关/解锁关卡的强制唯一前置。
- 非抖音环境允许测试 fallback，但不得把 fallback 当成抖音广告已通过。

## P1：审核与体验缺陷

### 5. 抖音平台一致性
- 提审版本的按钮、功能说明、截图、实际功能保持一致。
- 游戏名称、首页显示名称、后台资料保持一致。
- 网络能力如有使用，检查 HTTPS/WSS 合法域名。
- 隐私政策中的开发者/运营者主体、地址、联系方式与认证主体一致。
- 权限按实际能力声明，不多报、不漏报。

### 6. 截图与资料
- 三张截图至少覆盖：含游戏名首页/登录页、真实游戏内容、核心功能。
- 禁止重复截图、空白画面、开发调试画面或与提交版本不一致素材。
- 功能描述中不写尚未实现的广告、排行、分享、云存档等能力。

### 7. 去同质化
- 七款不得只换美术/UI/名称而复用相同玩法。
- 每款至少保持独立核心规则、关卡节奏、主要交互和视觉结构。
- 共用平台桥接、存档防御、生命周期等基础设施可以复用，但核心玩法代码应独立。
- 内部相似度检查仅作风险提示，不等同抖音官方阈值。

## 七款专项回归重点

| 游戏 | 必测专项 |
|---|---|
| 弹跳球 | 连续弹跳、碰撞边界、落点判定、失败/复活重复触发 |
| 影子小猫 | 双世界同步、镜像/追影/光影三模式、机关光照、出口同帧完成 |
| 合成宠物 | 合成幂等、拖拽冲突、满格状态、连续合成与存档恢复 |
| 极速跑酷 | 长时间运行、碰撞、暂停恢复、速度递增、复活后状态重置 |
| 重力企鹅 | 四方向重力切换、边界夹死、快速连续切换、关卡重置 |
| 镜像机器人 | 镜像输入、双角色碰撞/目标同步、死锁、重开状态 |
| 时间小偷 | 计时暂停、前后台切换、时间道具、超时与结算竞争条件 |

## 四层验收记录

每款必须分别记录：
1. Source：源码/静态/模型检查。
2. Creator：Cocos Creator 实际预览。
3. Douyin DevTools：抖音开发者工具实际运行。
4. Device：真机连续运行与关键流程。

只有 2–4 层有真实日志、截图或人工记录时，才允许标记对应层“通过”。
