# 影子小猫 30关可解性审计 Round 1

日期：2026-09-09

## 审计方法

本轮不是 Cocos 真机跑关，而是按照当前 `Core`、`LevelData`、`InteractionResolver` 的规则做状态空间搜索模拟。状态包含：现实猫位置、影子猫位置、光照状态、现实机关完成集合、影子机关完成集合、追影队列。可执行动作包含四方向移动、切换光照、互动、追影一步。

判定目标：完成全部现实/影子机关，并满足出口条件；追影模式还要求队列清空。

注意：这是逻辑可解性验证，不等于玩家真实操作体验，也不等于 Creator / 抖音开发者工具 / 真机通过。

## 本轮先发现并修复的问题

`lightGates` 原先只要大于 0，就会让所有机关都受明暗奇偶限制，导致字段“数量”语义失真，也会无意中提高后期解题限制。

已修正为：只有机关索引 `< lightGates` 的机关受光照约束，其余机关保持普通互动。这样 `lightGates=1/2/3` 才真正表示 1/2/3 个光照机关。

## 复核结论

1. 当前逻辑模型下，30/30 关都至少存在一条通关路径。
2. 19-20关延迟2步的状态空间明显扩大，说明机制复杂度确实提高，但也意味着真人操作时更容易迷失，需要更明确的追影提示。
3. 21-30关光影偏移可以满足双出口条件，当前偏移量 8/12 没有把影子永久推出出口判定半径。
4. 目前“最短动作深度”只反映逻辑搜索，不包含玩家思考、误操作、停顿和 UI 点击耗时，不能直接用于证明 60/75/90 秒限时一定合理。
5. 下一轮应重点做真人节奏估算：每关按保守 1.2~1.8 秒/有效操作估算，并为 19-20、26-30 增加误操作余量。
